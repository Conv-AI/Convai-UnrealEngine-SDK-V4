# Unreleased

- Reverted the character's transcript broadcasts to the beta.27 shape, fixing the chat line printing the reply once per broadcast ("Hello Hello. Hello."). `aa48ebdc` had changed `OnBotTranscript` from forwarding the raw `bot-transcription` sentence to broadcasting the whole turn assembled so far, added an `OnBotLLMText` broadcast beta.27 did not have, and finalised at `bot-llm-stopped` with that assembled turn instead of `""`. The shipped `Chat_WB` character call site passes `IsTranscription = false`, which is the widget's *append* branch (`SetText(GetText + " " + message)`) — correct for beta.27's disjoint sentences, and a concatenation of whole utterances afterwards. `OnBotTranscript` now forwards the sentence untouched with `IsTranscriptionReady = true`, `bot-llm-text` is discarded again, and `bot-llm-stopped` finalises with an empty string. **No Content change ships**; `Chat_WB` and `WBP_3DChatWidget` are untouched and integrators who forked them need do nothing.
- Two consequences of that revert, both deliberate and both reopening halves of FINDINGS F23. The character's `IsFinal` carries an empty string again, so a game wanting the finished answer must accumulate the sentences itself. And a **typed** prompt puts no character text on the transcript delegate at all: the server sends no `bot-transcription` on that path, and its only carrier there is `bot-llm-text`, whose sub-word tokens ("us", "ed", ".") cannot be appended by the widget without mangling the spacing — forwarding them rendered "It's a system us ed to ev aluate con versational AI p erformance." Delivering the text path needs the tokens buffered to a sentence boundary first, which is the follow-up this leaves open. `ConvaiTranscript::AdvanceBotTurn` and the `BotTurnText` members are removed with the assembly they served.
- Removed `ConvaiTranscript::AdvanceUserTurn` and the `UserTurnText` members with it; `OnUserTranscript` forwards the packet exactly as the server sent it, as it did before `253cde0e`. That commit bundled two player-side changes and attributed one symptom to both: its message blamed "the player's a word at a time" on delta packets, while the comment it left in `OnUserStoppedSpeaking` blames the same symptom ("blank, or holding a single word") on the empty final it removed in the same breath. Only the second mechanism is documented, and beta.27 ships raw forwarding *and* the empty final and renders correctly, so the assembly's justification was never established. Its `+=` also broke the common shape outright, concatenating cumulative packets into "HHi,Hi, how". The empty-final removal is kept.
- Measured while investigating, and worth recording: `user-transcription` arrives in two shapes on the same backend, and no field distinguishes them. A live-mic PIE session re-sends the whole utterance every packet ("H", "Hi,", "Hi, how"); scripted audio through the harness against character `bae40462` sends word-sized deltas (" Hey", ",", " what"). The plugin no longer normalises this, so a delta-shaped session reaches a listener as deltas. Whether any real player configuration produces that shape is unresolved and is a backend question.

- Added `ConvaiTestSteps::TranscriptShapeFinding`, which grades a speaker's transcript stream against its contracted shape — `WholeUtterance` for the player (each non-final broadcast must extend the previous, the final is non-empty, `IsTranscriptionReady` never set) and `Increment` for the character (no broadcast may re-send everything so far, the final is empty, `IsTranscriptionReady` always set). Wired into `text_roundtrip`. Not applied to the player: the plugin forwards that stream unshaped, so the shape is the server's to choose and asserting either one would fail on backend configuration rather than on the plugin. This is the coverage whose absence let the regression ship: every scenario graded `LatestFinalTextFrom`, and the final stayed correct throughout. `ConvaiTestSteps::AssembledTextFrom` joins the character's sentences for the scenarios that used to read its final, which is now empty by contract.

# Release 4.0.0-beta.27

- Updated the dependency-managed `BP_ConvaiChatbotComponent` so the previously shipped `UConvaiEscortToTask` / Convai Escort proxy is wired into the convenience Blueprint and usable without a project-specific handler. The unused Wait for Action row is disabled. The public workflow now fails before compilation when `E:/Dependencies_V4/Content.zip` does not contain a chatbot Blueprint with the Escort marker, preventing an older content bundle from being published accidentally.
- Record-while-streaming microphone changes, player-perspective surroundings, trigger-node simplification, animation-instance filtering, and the always-available debug truth layer are promoted from Unreleased into beta.27; the detailed notes below remain the engineering record.
- Added Knowledge Bank REST proxies and URL coverage, including custom-base-URL handling and Blueprint/test surfaces. The transient Vision Object Autotag REST proxy merge was reverted before release and is not part of beta.27.
- Restored UE 5.0 compatibility for microphone save-game lookup and WAV bulk-data access after the newer microphone changes.
- Added the explicit `UObject/Package.h` include required by UE 5.4's non-unity `NewObject(..., GetTransientPackage())` microphone save path; UE 5.3 compiled only because its include graph supplied `UPackage` transitively.
- Verified final `BuildPlugin -Rocket -Marketplace -TargetPlatforms=Win64` packages on UE 5.0 and UE 5.3-5.8. UE 5.0 used VS2019 14.29, UE 5.3-5.7 used VS2022 14.38, and UE 5.8 used VS2022 14.44. The machine-wide UnrealBuildTool configuration was restored byte-for-byte afterward.
- Hardened `UConvaiMoveOwnedAITask::OnDestroy` during GC purge/world teardown. In addition to invalidating the request ID when the controller, world, or path-following component is unusable, the controller is cleared before `UAITask_MoveTo::OnDestroy` when following it could enter unreachable object state. Base `ResetObservers` remains pointer-only through UE 5.8 and older `ResetTimers` versions are also pointer-only; valid controllers with an ordinary null path-following component retain timer cleanup. Move failures now log pawn, nav projection, path-following, movement-component, and controller ownership diagnostics before a reachable retry.

- Record-while-streaming (PR #90, Anish; #88 was the same change merged with additional review edits, then reverted): `UConvaiPlayerComponent::StartRecording` no longer refuses while `IsStreaming` — that refusal made mic tests a no-op whenever push-to-talk was off and the stream was always open. While streaming, StartRecording saves `bMuteBeforeRecording` and forces `bMute=true` (restored in FinishRecording) so the character doesn't hear the test; FinishRecording only stops the capture device when nothing else is using it; `OnProcessedAudioDataReceived` honors `bMute` so a muted mic isn't sent when audio processing is active. NOTE: the #88 review-fix commit (private suppress flag + pump restarts) was found to REGRESS streaming/mic behavior in PIE and was reverted with it — the extra `StartVoiceChunkCapture()` restarts on an already-active submix recorder are the prime suspect. Review's theoretical edge cases (Blueprint flipping bMute mid-recording; stream-stop mid-recording truncation) remain open but must be fixed only with PIE verification per step.
- Added player-perspective surroundings clauses (setting `bDescribePlayerPerspective`, default ON, Project Settings > Spatial Awareness). In `UConvaiContextSubsystem::EvaluateSpatialAwareness`, each observer picks a PerspectivePlayer (nearest player entity) and every published spatial fact gains an appended clause `" From <PlayerName>'s position, <subject display name> is <band>[, <direction>]."`. Design decisions, each fixing an observed LLM failure: the clause names its subject rather than using "it" (a pronoun let the model answer a 5m-target question with the 15m target's geometry); it never contains "you" (second-person diction was the root frame-swap: the model told the player "right in front of you" for things in front of the character); direction words are frame-free ("ahead", "to the left" — new `ConvaiSpatial::DirectionPlain`) computed in the player's yaw-only camera frame (`APlayerController::GetPlayerViewPoint`, stored as `FSpatialEntity::ViewRotation` — pawn forward is wrong for "what am I looking at" whenever the camera decouples); distance uses `ConvaiSpatial::BandWord` with no reachability verdict (chatbot nav does not apply to the player's frame); and the clause is never distance-gated — beyond the moderate band it degrades to a bare "far away" with direction dropped, so an earlier "close by, ahead" is actively overwritten instead of lingering stale in the model's conversation history (silence does not retract information from an LLM).
- Churn containment for the same feature: `FObserverSpatialCache::FFact` now stores `EgoSentence` alongside the published sentence; when only the player clause changed (player walked/turned, or the setting flipped), the fact republishes with `EC_RunLLMOption::Never` + SendNormally so one player turn — which changes the clause on every fact in range in the same poll — cannot wake the AI. `FindAnchor` gained `bSkipPlayers` (passed as `PerspectivePlayer != nullptr`) so the player is not also a directional relation anchor while the dedicated clause exists (the same frame would be stated twice in different diction); support-relation wording still may reference the player. The managed-Instructions frame-selection line (one bullet: "you/your" = your frame; use the "From <name>'s position" clause when answering a player) is gated on the new `UConvaiContextSubsystem::HasPlayerPerspectiveFacts` (cache flag `bHasPlayerPerspectiveFacts`, set per pass, cleared on the awareness-inactive path) so it can never advertise a clause that is not in the context. Known deferred: nearest-player selection can flap between equidistant players in multiplayer (wants retained-player hysteresis); third-person cameras use camera yaw but pawn origin. Design review notes: two-model consultation (Claude agent + Codex session 019f7a85) both independently chose this bounded per-player clause over enlarging the relation cluster distance for players, which cannot guarantee coverage (nearest-outranking-anchor semantics let a nearby character displace the player anchor) and carries no distance band.
- `ConvaiSpatial`: added `DirectionPlain` (frame-free direction words) and `BandWord` (bare band phrase); `BandPhrase` now composes from `BandWord` so the band vocabulary has one source of truth (Unreachable stays special: direction-led, no band word). A vocabulary-table unification of the three direction functions was considered and rejected (rule of three — each encodes distinct grammar and the explicit tables are what reviewers need to read).
- Invoke Speech (`ExecuteNarrativeTrigger`) and Invoke Narrative Design Trigger dropped their obsolete `InGenerateActions`/`InReplicateOnNetwork` parameters (graph-breaking for wired pins); `FPendingTrigger` lost the matching fields. Invoke Speech now stages its cue via `AddContextEvent(..., EC_RunLLMOption::Always, Delivery, /*bEphemeral*/ true)` — one-flush, never committed to the tracker — and exposes `EConvaiContextDelivery` (AdvancedDisplay, default SendNormally).
- `UConvaiUtils::GetBodyAndFaceSkeletalMeshComponents` filters candidates to components with a running `AnimInstance` before scoring (new `bRequireAnimInstance = true` param; falls back to the unfiltered list when nothing qualifies so callers still get a body).
- Debug overlay: removed every `ConvaiDebugMode` gate from `ConvaiDebugOverlay.cpp` — verbatim surroundings sentences, FACTS, and EVENTS now compile into all builds (the flag itself and its other uses across audio/face-sync/subsystem logging are untouched). Rationale: the truth layer is the overlay's main diagnostic value and the flag defaults to 0 in `Convai.Build.cs`, so released overlays were silently missing it.

# Release 4.0.0-beta.25

- Release engineering now publishes downloadable binary packages and source-only Marketplace packages as two separate releases, validates tag reuse, and fails on missing assets. The public snapshot continues to omit maintainer docs, dependency-managed Content, and ThirdParty binaries while retaining source-controlled `Content/Skills`; the build runner removes any dependency copy of Skills and overlays the checked-in set only for UE 5.8.
- Hardened cross-version packaging for the final UE 5.0-5.8 matrix: flattened multiline UHT metadata that UE 5.0 cannot parse, gated editor-only metadata assertions in non-editor test builds, added the explicit `UObject/Package.h` include required by newer non-unity builds, and kept all-engine context-menu cleanup ahead of the UE 5.2+ editor-UI shutdown path.
- Fixed movement endpoint settling and dynamic-context ordering. The synthetic Movement state and declarative surroundings fact now follow the same confirmed detector edge; a start/stop edge replaces older pending or idle-held same-key motion data and its response request, while direction-only relabels may still coalesce. Routing a newer state or keyed fact to idle delivery also withdraws any older same-key value still waiting in the normal debounce batch, so stale context cannot flush first; later spatial/relation refreshes stay paired with a held Movement value instead of briefly publishing a contradictory fact. Silent states remain canonical without being repeated in another item's response delta. Prospective direction changes now need continuous raw/rolling agreement and sensitivity-scaled progress; bounded terminal rebounds and direction-churning physics loops settle without replacing the completed trip direction, while a stable turn or reversal continues through the start/stop hysteresis band and still escapes the envelope. A different coherent segment after that escape starts a fresh local settling episode, so endpoint bounce cannot inherit the completed trip's travel distance and suppress its stop. At Low sensitivity bounded settling enters within 60 cm and its stopped latch releases beyond 70 cm, preventing immediate restart flapping.
- Removed the advanced "Force Refresh" pin from Resolve Goal Location (and the bForceRefresh parameter from the C++ resolver API): the component cache is now revalidated on every call — a destroyed component, a changed Component Name filter, or a swapped actor already triggers a rescan automatically, so the manual escape hatch bought nothing. Graphs that wired the pin just delete the connection; nothing else changes.
- Resolve Goal Location now outputs a ready-to-wire "Target Actor" pin: wire Target Actor + Destination straight into one AI Move To with no branch — on successful resolution Target Actor is null exactly when the goal is a fixed location (a Movement Point won, or the entry references a component), which is when AI Move To should use the Destination pin (it prefers a non-null actor, which used to silently ignore Movement Points when both pins were wired); a failed resolution also returns null. The old pins keep their exact behavior under clearer names — "Object Actor" (always the entry's actor, for non-movement uses) and "Uses Destination" (the explicit-branch bool) — and move to the node's advanced section; existing graphs keep working unchanged.
- Fixed the chatbot's conversation-state queries, which were stubbed to false: Is Listening is now true while the user is speaking in the character's session (server VAD), Is Thinking begins only when the server starts generating and lasts until the character starts speaking, the server declines to respond, or a ~5 s safety timeout, and Is In Conversation is the OR of listening/thinking/talking, including audio still streaming in from the server so it cannot flicker false in hand-off gaps. Interrupting during the thinking window now fires On Interrupted as intended.
- Added a normalized speaking lifecycle to the Convai Player component. Server voice-activity events remain primary, while the first non-empty partial transcription repairs a missing start and a non-empty final transcription repairs a missing stop. Duplicate edges are idempotent, and a 250 ms real-time stop grace lets a continuing partial cancel a premature stop even while gameplay is paused or time-dilated. `Is Speaking` and the inherited Started/Finished Talking delegates now share this lifecycle. Also fixed the player component's `IsPlayer()` override, which returned false.
- Added a Delivery option ("Send Normally" / "Wait Until Conversation Is Idle") to the dynamic-context APIs — Add Context Event, Set Context State(s), Set Context Fact, Set Object In Attention, gaze attention (new Gaze Delivery on the player component), and per tracked property. Wait Until Conversation Is Idle holds the update while anyone is talking or the character is thinking, so an event/gaze cue/property change can't make the character interrupt itself mid-sentence; it's delivered once the conversation has stayed quiet for the chatbot's "Quiet Time Before Delivery (s)" (default 2 — covers the user merely pausing between sentences), with deliberately no upper bound on the total wait, so a waiting update never interrupts an ongoing conversation. Held events land at the end of the event history when released, so they read as the most recent thing that happened. Applies only when Should Respond is Auto/Always; silent (Never) updates are unaffected. On tracked properties, Never also resets Delivery to Send Normally and Flush Immediately to false and disables both rows. A newer write to the same state/fact/attention supersedes a held older one, Reset Dynamic Context cancels held work, and held updates survive transient disconnects.
- Added two experimental built-in actions (Details panel > Convai > Actions > Experimental, both off by default, applied at next session start): "Remind Self {reminder}" lets the AI queue a note to itself after other actions — e.g. [Move To Painting, Remind Self "describe it to the visitor"] prompts the character to respond on arrival; the reminder is delivered at the next genuine pause in the conversation, however long that takes; "Watch Property {property}" lets the AI arm a one-shot watch on a tracked property by its context key, or on `Key = exact value`, and get notified on the next matching genuine change even when the property's Should Respond is Never/Auto (target watches wait for a real departure and later return; the watch disarms after firing; unresolvable names are reported back so the AI can retry). Enabling either built-in automatically injects a concise declarative usage hint, so character backstories do not need duplicate instructions. Built-ins never appear in the Environment's Actions array, and a Blueprint handler with the same name still overrides them.
- Added configurable movement awareness for Convai Objects. **Enable Movement Awareness** is on by default and can disable motion detection, wording, state publication, and responses without affecting ordinary position or reachability context; movement watches remain dormant while the state is unavailable. Its five-level **Sensitivity** control ranges from Very Low for noisy physics objects through Medium (the backward-compatible default) to Very High for extremely subtle motion. While confirmed moving, the existing spatial fact gains concise observer-relative direction, sparse coarse-speed wording, or rotation. A short rolling net-transform trend filters bounded collision jitter for both direction and stop detection without hiding coherent slow travel; the trend window doubles as stop confirmation, and an excursion guard preserves meaningful oscillation. **Add Movement State** optionally exposes `<Object>.Movement`; independent `Never` / `Auto` / `Always` start and stop policies are its notification controls, with Delivery and Flush enabled only when a transition can request a response and reset to normal/off when both are Never. Because the key already says Movement, its compact values avoid repeating "Moving": `Stopped`, `Moving`, `Upward`, `Downward`, `Toward You`, `Away`, `Left`, `Right`, or `Rotating`. Discrete observer-relative labels stay current as geometry changes, and direction changes update the same property (`is now Upward (was Left)`); speed stays in the spatial fact. Opted-in objects also keep `stopped` explicit there while ordinary stationary props stay terse. Targeted Watch Property actions can wait specifically for `Stopped` or a direction, and every confirmed edge preserves its transition (`is now Upward (was Stopped)` / `is now Stopped (was Downward)`), including coalesced and idle-held round trips.
- State batching now cancels ordinary `A -> B -> A` round trips, including their stale response rank, because they have no net change. Transition-significant internal states can opt out without a parallel delivery path; movement does so to retain a brief excursion and its immediately preceding directional moving/stopped state.
- Duplicate object descriptions now dedupe in the AI's environment: when several objects register the same non-empty description (five identical coins), later registrations send "Same as coin." instead of repeating the full text — shorter prompts, same knowledge. Generated movement-point destinations are never the dedup anchor.
- Verified the plugin builds against UE 5.0 through 5.8: added two explicit includes that older engines (5.0–5.5) don't pull in transitively — FHitResult (split into its own header in 5.1) and APawn in the debug overlay and player component. No behavior change on any engine version.
- Spatial reachability now reacts to navmesh updates: when the mesh rebuilds (a door opens, an obstacle moves) the affected cached verdicts refresh on the next poll even though nothing else moved — previously a verdict only refreshed when the character or the object moved. Spatial facts now distinguish all three outcomes: already arrived (`You are already at/with ...`, with no walking verdict), reachable (`reachable by walking`), or blocked (`with no walking path there`), so a reopened route replaces the model's stale blocked belief without calling an already-reached target merely reachable. The initial spatial snapshot is always seeded with `Never`, so even `Auto`/`Always` spatial policies apply only to later changes and cannot make the character speak at session start.
- Movement Points can become separately AI-addressable destinations: tick "Create Separate Destination" on a point and give it a Destination Name — a door point named "Other Side" gives the AI a "Door Other Side" target with its own spatial fact, distance/direction, and navmesh reachability, so "go to the other side of the door" finally means the other side. The checkbox is an explicit opt-in (everything unticked belongs to the object itself, exactly as before — the elevator pattern: the point ON the platform stays unticked while world-fixed landings become "Moving Platform Lower Landing" / "Moving Platform Upper Landing"); generated descriptions now explicitly distinguish each fixed or attached destination from the base object. Merged sets pool and group destinations by name across members; destinations never fall back to the object body; the debug overlay shows them like any other object. Destinations are authoring-time identity — runtime renames apply on re-registration. Movement-point and object-entry properties were also renamed/re-documented for first-read clarity ("Object Is", "Use Object as Fallback", plain-language tooltips throughout).
- Spatial awareness now nav-checks other characters and the player, not just objects — every person is described as already with the observer, reachable by walking, or blocked by no walking path. The debug overlay shows the same verdict on every subject.
- Added the Convai Debug Overlay (Ctrl+Alt+K in editor and development builds, or the `Convai.DebugOverlay` console command): screen markers over every registered Convai object, and a panel for the selected character showing its context states (state changes pulse a dot tinted by their Should Respond setting; the selected object's own states highlight so its tracked properties are easy to spot) and a surroundings list showing every spatial fact the AI was told — objects, other characters, and the player — verbatim under a bold subject label that turns red with "no path" when the nav verdict says the subject can't be walked to. Surroundings labels carry the nav verdict as a chip — plain name = reachable, cyan "reached" = already there, red "no path" = unreachable. The verbose truth layer (verbatim fact sentences, facts set via Set Context Fact, and context events committed/staged/one-shot) compiles in only under the internal ConvaiDebugMode build flag, keeping the released overlay compact; in those internal builds the panel covers the entire dynamic context: if the AI is told it, the panel shows it. The selected character's action queue floats over its head, with a green flash when an action completes and a red, growing flash when it fails or aborts. PgUp/PgDn cycles objects, Shift+PgUp/PgDn cycles characters; the hotkey is configurable under Project Settings > Plugins > Convai, and the overlay stays out of Shipping builds unless the "Allow In Shipping Builds" setting is on.
- Added an Enabled master switch to Convai Object components (on by default, toggleable at runtime via Set Convai Object Enabled): off makes the object invisible to the whole system — no environment entry, no tracked-property broadcasts, no spatial awareness, no gaze — and a mid-session disable cleans it out of every chatbot exactly like destroying the component would.
- Added a nav-path debug-draw toggle to Convai Object components: when on, each poll draws every chatbot's walking path to the object (green = reachable, red = no path, cyan = already there) with start/end markers.
- Added Movement Points to Convai Objects: designer-authored access points (multiple per object, e.g. one per side of a door) that define where a character stands when moving to the object. The resolver walks to the reachable point with the shortest path; the object reports unreachable when all points are (with an opt-in fallback to the object itself). Points are edited in the viewport as clickable grab handles with the native transform gizmo — in both the level editor and the Blueprint editor — with undo and archetype propagation (relative-to-object or world-locked, per-point enable toggle).
- BREAKING: renamed the object-entry goal properties for clarity — `EConvaiMoveTarget`/`MoveTargetMode` are now `EConvaiObjectReference` (`WholeActor` / `SpecificComponent`) / `ObjectReference`: they define what the object IS (gaze/attention/vision scope) and are only the movement fallback when no Movement Points are authored. Resolve Goal Location's enum `Out Mode` output is now a plain `bOut Move To Location` bool (false = wire the Target Actor pin, true = the Destination pin). Existing Blueprints referencing the old names must be re-wired.
- Removed the Step Onto Bounds movement heuristics (bounds projection, footprint containment) — Movement Points replace them with explicit, predictable targets. Resolve Goal Location gains Out Goal Travel Distance and Out Movement Point Index outputs; merged objects now pick the nearest member by actual walking distance instead of straight-line distance.
- Tracked properties can now reach into sub-actors and sub-objects: property paths may hop through actor, component, and instanced-object references (e.g. "Turret.Health"), with each hop re-validated every poll so null or destroyed references pause tracking instead of breaking it. Pure functions are pickable on hopped-to objects too.
- Added an optional Alias per tracked property: when set, the chatbot sees "<ObjectName>.<Alias>" instead of the full dotted path.
- Tracked properties now survive Blueprint variable renames: each path segment latches onto the Blueprint variable's (or Blueprint component's) GUID and re-latches by GUID in-editor when the name stops resolving (best-effort).
- Dynamic-context prompt hygiene: state keys are whitespace-sanitized (Pascal-cased, "door state" → "DoorState") at the chatbot API so they read as single tokens, and multi-word state values are quoted when rendered ("DoorState is \"half open\"") while single-word values stay bare.
